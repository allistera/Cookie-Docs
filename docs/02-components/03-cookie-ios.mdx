Cookie-iOS is the native SwiftUI client for Cookie. Its authenticated shell switches among **Email**, **Calendar**, and **Notes**; it owns no server-side logic or database. The project targets iOS 17, uses Swift 6 strict concurrency, and is generated from `project.yml` with XcodeGen.

## Layout

<FileTree>

- Cookie/Sources/
  - App/ — application entry point
  - Auth/ — Auth0 session and login state
  - Models/ — mail, contacts, documents, rich text, and JSON models
  - Networking/ — email, message, search, send, calendar, document, and contact clients
  - Views/ — inbox, message detail/body, compose, calendar, notes tree/editor, rich-text editor
  - Info.plist — Auth0 callback configuration
- Cookie/Resources/ — app icon and colour assets
- CookieTests/ — networking, navigation, mail actions, search, compose, rich text, documents, and calendar tests
- project.yml — XcodeGen source of truth and Auth0.swift dependency

</FileTree>

## Shipped screens

- **Email** — paginated inbox, category filters, pull to refresh, debounced keyword type-ahead, explicit hybrid search, message detail, attachment/body loading, Done actions, and a full-screen composer.
- **Reading** — sanitized HTML in a bounded web view; remote images are blocked by default and can be loaded explicitly. Reply opens the composer with the message context.
- **Compose** — contact suggestions, rich-text body, new mail/reply sending, and explicit success feedback.
- **Calendar** — lists calendars/events and turns natural-language text into a reviewable event draft before creating it.
- **Notes** — hierarchical document/folder browser and block-aware editor for supported rich-text rows; unsupported table/image/Kanban/Excalidraw blocks remain identifiable rather than being silently discarded.

## API clients

| Client | Current endpoint family |
| --- | --- |
| `MessagesAPI` / `ContactsAPI` | `messages-api.infinitywave.online` Worker |
| `DocumentsAPI` | `tasks-api.infinitywave.online` Worker |
| `SendAPI` | Vercel compatibility `/api/send` |
| `EmailsAPI` / `SearchAPI` / `CalendarEventsAPI` | legacy `mail.infinitywave.online/api/*` paths |

:::warning
The backend migrations moved emails, search, and calendar APIs to `emails-api`, `search-api`, and `calendar-api`, but the current iOS source still targets their former Vercel paths. The table above documents the implementation as it exists; those clients need a coordinated application change before the iOS app fully matches the current Worker topology.
:::

Auth0 access tokens use the same Cookie API audience as the web app. Focused unit tests keep response contracts independently testable.

## Build and test

Requires macOS with Xcode, XcodeGen, and SwiftLint:

```sh
brew install xcodegen swiftlint
xcodegen generate
xcodebuild -project Cookie.xcodeproj -scheme Cookie \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' test
swiftlint --strict
```

Regenerate the Xcode project after adding, moving, or removing sources. `project.yml` pins Auth0.swift from `3.1.0` and is the project-definition source of truth.

Cookie-iOS currently has no checked-in GitHub Actions workflow or automated deployment; validation and distribution are local/Xcode responsibilities.
