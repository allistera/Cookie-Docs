Cookie-iOS is the native SwiftUI implementation of Cookie's **"Cards & Stacks"** design: a swipeable-card inbox, an AI-summarized reading view, and an AI compose sheet. It authenticates with Auth0 and calls the [Cookie-Web API](/components/cookie-web#api-surface) for the inbox, AI compose, new messages, and threaded replies — it holds no server-side logic or database of its own. Protocol-backed mocks keep the UI previewable and testable without a live backend.

## Layout

<FileTree>

- Cookie/
  - CookieApp.swift — app entry point
  - DesignSystem/ — theme tokens, CookieMark logo, SparkleIcon, BrandAvatar
  - Models/ — Email, tags, filters, sample fixtures
  - Services/ — AIService / MailService protocols and their mocks
  - State/ — `@Observable` InboxStore
  - Features/
    - Inbox/ — InboxView, cards, filter chips, swipe actions, FAB
    - Reading/ — ReadingView: summary card, critical-issue card, reply bar
    - Compose/ — ComposeView + ComposeModel (AI draft generation)
- CookieTests/ — unit tests (inbox filtering/swipe invariants, compose state machine)
- Scripts/capture-screens.sh — fidelity screenshot capture
- project.yml — XcodeGen project definition

</FileTree>

## Services

| Service | Responsibility |
| --- | --- |
| `APIClient` / `APIConfig` | HTTP client and endpoint configuration for the Cookie-Web API |
| `RemoteMailService` | Live `MailService` implementation backed by `APIClient` |
| `MailService` (protocol) | Inbox, reading, and compose data access — mocked for tests/previews |
| `AIService` | AI compose generation and summaries |
| `ContactService` | Compose recipient suggestions (`/api/messages?resource=contacts`) |
| `NotificationService` | Push/local notification handling |

## Screens

- **Inbox** — header, semantic search field, filter chips, and a vertical stack of email cards. Unread mail carries a 4px coral bar; cards with a thread summary show a violet "Cookie summary" strip.
- **Reading** — subject, tag chips, an AI **Cookie summary** card (bulleted, violet-tinted), the message body, an AI-highlighted critical-issue card with a resolve action, and a sticky reply bar with an inline AI **Draft** button.
- **Compose** — To/Subject fields, an AI prompt bar ("Generated by Cookie" + Regenerate), the generated draft body, and two adjust actions ("Make shorter", "Adjust tone").
- **Swipe actions** — left-swipe reveals **Snooze** and **Done** (Archive was intentionally removed).

These map to the same AI backend as the web app's generate/summarize/search endpoints — see [AI features](/ai-features).

## Build & run

Requires Xcode with an iOS 17+ simulator, plus XcodeGen and SwiftLint:

```sh
brew install xcodegen swiftlint
xcodegen generate
open Cookie.xcodeproj
```

Run the **Cookie** scheme (⌘R), or from the CLI:

```sh
xcodebuild -project Cookie.xcodeproj -scheme Cookie \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' build
```

Regenerate the Xcode project with `xcodegen generate` after adding, removing, or moving source files — `project.yml` is the source of truth.

## Tests and linting

```sh
xcodebuild -project Cookie.xcodeproj -scheme Cookie \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' test
swiftlint --strict
```

SwiftLint also runs as an Xcode build phase; `--strict` is the check required before committing.
